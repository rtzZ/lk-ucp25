# Архитектура

## Общая картина

```
Яндекс.Диск (2 публичные таблицы)
        │  09:30 и 11:00 МСК, APScheduler 3.x (lifespan FastAPI)
        ▼
extract_downloader_url  — headless Chromium рендерит edit-страницу,
                          из HTML извлекается подписанный URL
download_xlsx           — скачивание через httpx (query менять нельзя:
                          подпись покрывает его целиком)
parse_*_xlsx            — openpyxl, чистые функции (юнит-тесты без файлов)
upsert_*                — замена данных в PostgreSQL (с защитой от
                          частичного парса, см. ниже)
        │
        ▼
FastAPI (auth, schedule, grades) --JSON--> React (Atlassian DS)
   ^ Telegram-бот (bot.py, long polling): привязка аккаунта, временные пароли
```

При недоступности ссылок ошибка логируется (`sync_source` не пробрасывает
исключения), API продолжает отдавать последние успешные данные из БД.
Пустые `YANDEX_*_URL` — пропуск с warning.

Почему Chromium, а не API Диска: публичный `cloud-api.yandex.net` отвергает
ключи `disk.360.yandex.ru` (400), а прямые ссылки downloader'а работают только
с точной подписью из отрендеренной страницы (иначе 403). Проверка без cookies:
`GET` edit-страницы обычным HTTP-клиентом возвращает JS-заглушку без ссылок.

## Формат таблицы расписания

Файл «Расписание УЦП-25…»: парсятся только листы `N семестр` (группа
из имени файла). Листы чужих групп (напр. «ЛФТ-25 2 сем») пропускаются
с warning; группы-сироты без студентов и пар чистятся при синхронизации —
в кабинете только своя группа. Шапка:
строка 1 — дни недели (merged), строка 2 — время пар (`HH:MM-HH:MM`).
Колонка `воскресенье` есть не везде. Колонки правее воскресенья — зона
аттестаций, в пары не идёт.

Далее блоки недель: строка с датами (`datetime` в day-колонках, номер недели
в колонке A — опционален) + строки пар. Ячейка пары — многострочный текст:
`Предмет / Организация / Номер / Преподаватель` + маркеры. Парсинг
(`parse_lesson_cell`): вид — `lesson | attestation | event | deadline`,
статус — `active | cancelled (ОТМЕНА) | moved (ПЕРЕНОС)`. Первое URL
в тексте ячейки сохраняется в `ScheduleItem.link` (поле «Ссылка
на подключение»). Одиночные `Сессия/Каникулы` — служебные, пропускаются. Не-строковые ячейки
(время `22:10`, числа) — не пары, пропускаются.

## Формат таблицы успеваемости

Файл «Успеваемость сводная УЦП-25»: листы-семестры (листы `Команды…` —
не оценки, пропускаются). Строка с `ECTS` — строка заданий; шапка блока —
ближайшая merged-строка выше с названием предмета (строки формул
`ИТОГОВАЯ…/Кт…/УСПЕВАЕМОСТЬ` отбрасываются). Тип аттестации: ячейка слева
от шапки, скобки в названии `(зачет с оценкой)` или строка заданий.

Ключевые правила, выведенные по реальным данным:
- Шкалы четыре, связаны парами: итоговая 1–5 ↔ словесная
  (Отлично/Хорошо/...), баллы 0–100 ↔ ECTS (A–F/Passed). У зачётных
  дисциплин только две шкалы (баллы + зачтено). Якорь блока — колонка
  баллов («Итого»/«Всего», точное совпадение важнее префикса: «Всего за КТ»
  не якорь); итоговая — первая колонка после неё с пустой шапкой или
  «Итоговая оценка» (не «Итоговая защита»!); словесная и ECTS определяются
  по значениям, а не по шапкам (шапки врут: пустые, «ECTS» над словесной).
- Название предмета чистится от организации и преподавателя; организация
  в скобках внутри названия («... проекта (Нетология)») вырезается,
  строка остаётся. Ловушка префиксов: «Итоговая ...» начинается
  на «итого», но баллами не является — исключено явно.
- Пустая итоговая ячейка = оценки ещё нет: `value/verbal/ects` пустые,
  баллы (если проставлены) сохраняются; фронт показывает «Нет оценки».
  Не «2»: иначе в текущем семестре у всей группы двойки до сессии.
  Блоки со своим списком (факультатив) затрагивают только своих участников.
- ID студентов в таблицах нет. `Student.code` — нормализованные
  «фамилия имя» (отчество игнорируется: одни и те же люди записаны то
  с отчеством, то без).
- Оценки блоков привязаны к строкам основного списка (колонка B).
  Исключение — блоки со своим списком (факультатив): колонка имён левее
  блока, почти не пересекающаяся с основным списком (порог 90%), —
  привязка позиционная. Вспомогательные списки (команды в блоке проектной
  дисциплины) игнорируются.
- Сопоставление ФИО: точное → перевёрнутое «Имя Фамилия» → нечёткое
  (difflib ≥ 0.9, покрывает ё/е и опечатки). Несопоставленное — пропуск
  с warning, дубликатов по `(student, subject, semester)` быть не должно.
- Значения оценок хранятся как у преподавателя (`5`, `зачтено`, баллы,
  разный регистр) — нормализация на отображении.

Проверено на реальных файлах: 682 записи расписания (УЦП-25 + ЛФТ-25),
797 оценок, 50 студентов, 19 предметов.

## Backend

- `db.py`: `AsyncEngine` + `async_sessionmaker(expire_on_commit=False)`,
  `get_session` — зависимость FastAPI. Связей `relationship` в моделях нет
  осознанно (ленивая загрузка падает в async) — только FK + явные select.
- Таблицы создаются `create_all` при старте (ленивый путь; Alembic подключать
  при первой эволюции схемы). Первая эволюция уже случилась:
  `Subject.description` (JSON) — колонка добавляется `ensure_description_column`
  (SQLite `PRAGMA` / Postgres `information_schema` + `ALTER TABLE`), значения —
  `fill_subject_descriptions` из `subject_descriptions.py` (только пустым;
  после каждого синка оценок — новым предметам; предметы без оценок синк
  удаляет).
- `logging.py`: loguru `serialize=True` — каждая строка stderr это JSON;
  middleware в `main.py` пишет каждый запрос (`method/path/status/elapsed_ms`).
- Планировщик: `AsyncIOScheduler`, синхронизация — два cron-триггера
  (`SYNC_TIMES`, по умолчанию `09:30,11:00` в `SYNC_TIMEZONE=Europe/Moscow`;
  `misfire_grace_time=3600`, `coalesce=True`, `max_instances=1`),
  завершение пар — `interval` (`EXPIRE_INTERVAL_HOURS`, по умолчанию час).
  `SKIP_SCHEDULER=1` отключает планировщик (тесты/E2E).
  `_sync_job` глотает все исключения (планировщик обязан переживать всё).
- Синхронизация: расписание и оценки заменяются целиком, студенты —
  upsert по `code` (обновление на месте, пропавшие из ведомости удаляются).
  Так `Student.id` стабилен между синками (он хранится в localStorage
  клиента) и telegram-привязки (`telegram_username/user_id`, их нет
  в ведомости) сохраняются. Пустой результат парсинга не коммитится
  (`upsert_*` возвращают 0, старые данные остаются); то же при резком
  сокращении — записей (пар, студентов или оценок) стало меньше
  `SYNC_MIN_RATIO` (0.5) от прежнего при базе от 20: так сломанный лист
  не стирает данные молча. Ожидаемое сокращение (новый учебный год) —
  `python -m app.admin sync --force`; `SYNC_MIN_RATIO=0` выключает проверку.
- Chromium и разбор XLSX (openpyxl) идут в `asyncio.to_thread`: синхронные
  и тяжёлые, в event loop они останавливали бы API на время синка.
  Ошибки синка пишутся с traceback (`logger.exception`).
- Группа кабинета — `LK_GROUP` (по умолчанию `УЦП-25`): ведомость группу
  не называет, все студенты попадают в неё; группа расписания — из имени
  файла (fallback — `LK_GROUP`), при расхождении — warning в лог.
- Ссылка на XLSX: в HTML edit-страницы ищется `downloader.disk.yandex.ru`
  (или локальный прокси `localhost:12701`), результат всегда на боевом хосте.
- Время расписания (live/completed) — в поясе `SYNC_TIMEZONE` (`app/tz.py`),
  не сервера: в Docker часы в UTC.
- Ссылки из ячеек чистятся `_clean_link` (только `http(s)`): `javascript:`-
  и прочие схемы отбрасываются, иначе href на фронте даст stored XSS.
- Auth: ФИО + временный пароль от Telegram-бота -> Bearer-токен.
  `bot.py` — long polling внутри backend (вебхук снимается при старте):
  `/start` -> проверка членства в группе курса (`getChatMember`) -> ввод
  «Фамилия Имя» -> привязка `telegram_user_id` к студенту (кто первый;
  занятое ФИО перепривязывает только админ: `python -m app.admin unbind`;
  10 попыток ввода ФИО в час на аккаунт). `routers/auth.py`: пароль 6 цифр,
  TTL 5 мин, одноразовый, 5 неверных вводов — сгорает, повтор отправки
  не чаще 30 с; ответ на запрос пароля одинаков для любых ФИО. Членство
  в группе проверяется и при каждом запросе пароля (ушедшие теряют доступ).
  Сессии — таблица `auth_sessions` (sha256 токена, `expires_at`,
  `SESSION_TTL_DAYS`), истёкшие чистит `_expire_job`; синк при удалении
  студента удаляет и его сессии. Все эндпоинты данных — через зависимость
  `current_student`: оценки только свои, расписание — группы студента.
  Пароли и попытки — in-memory (один инстанс; для нескольких — Redis).
  `telegram.py` не пропускает текст ошибок httpx наружу: в URL Bot API токен.
  `AUTH_DEV_MODE=1` (игнорируется при заданном токене бота) — пароль
  в ответе API, лимиты выключены: разработка и E2E.
- Rate limit (`ratelimit.py`, in-memory, с IP): запрос пароля 5/мин,
  вход 10/мин — сверх лимита 429. IP клиента — из `X-Forwarded-For`:
  в образе `--proxy-headers` + `FORWARDED_ALLOW_IPS` (приватные сети
  Docker), иначе за nginx у всех был бы IP шлюза и один лимит на весь сайт.
- Время в расписании каноническое `HH:MM` (`parse_time_range` добивает нуль —
  иначе строковые сравнения expiry/live врут на утренних парах); фронт
  в `isUpcoming` паддит защитно (старые строки в БД).
- `GET /schedule` — чистое чтение; дубли оценок отсекаются в `upsert_grades`
  (иначе unique ронял бы весь синк).
- Фронт: вход по подсказке-однофамильцу использует группу студента (`s.group`,
  а не выбранную в дропдауне); таблица оценок — постранично (`page/onSetPage`,
  сброс на 1-ю при смене фильтров); UID событий `.ics` — FNV-хэш смысловых
  полей (id перегенерируются синком, дубли в календарях); `URL:` в `.ics`
  не экранируется (только fold), дублирующихся DOM-id в drawer нет.
- Важно: APScheduler 4.x существует только в альфах на PyPI — зафиксирован
  стабильный 3.11.x (API `AsyncIOScheduler`). Документация Context7 отдавала
  API master-ветки (4.x) — не использовать без проверки установкой.

## Frontend

Vite + React 18 + TypeScript + Atlassian Design System (`button/new`,
`datetime-picker`, `drawer`, `dynamic-table`, `form`,
`heading`, `lozenge`, `primitives/compiled`, `select`, `tag`, `textfield`,
`toggle`; сверено с Context7). Бандл режется `manualChunks` (приложение /
`vendor` / `atlaskit` отдельно). Состояние — `useState`
без роутера (3 экрана): `Login` → вкладки `Schedule` / `Grades`.
Сессия хранится в `localStorage`. Mobile-first CSS поверх компонентов
(max-width 720). API-клиент (`api.ts`) — fetch с таймаутом 15с
(AbortController); ошибки сети показываются баннером `.error`, а не пустым
списком. Логин — нативная `<form>` (Enter сабмитит), favicon — `public/favicon.svg`. Вход — идентификация себя (фамилия+имя), пароля нет:
данные общие, вход нужен чтобы показать свои оценки.
Клик по паре открывает `@atlaskit/drawer` (композиция `Drawer` +
`DrawerCloseButton` + `DrawerContent`): детали занятия и поле «Ссылка
на подключение» (readonly + ссылка «Подключиться к паре»).
Клик по предмету (оценки — ячейка таблицы, расписание — карточка пары)
открывает Drawer с описанием предмета из Figma-макета
(`components/SubjectDescription`: описание показывается в `@atlaskit/textarea`
(`isDisabled`, `resize="none"`, `minimumRows={4}`, `maxHeight="none"`
+ `style="overflow: hidden"`; высота ставится в `min-height` по
`scrollHeight` в `useLayoutEffect` + `ResizeObserver` + `document.fonts.ready`
— textarea растягивается под контент без полосы прокрутки; платформенная
`height` на этом текстеаrea в Chromium перекрывается, а `min-height` нет) с
`Label` «Описание
дисциплины»; подсписки схлопываются в текст с маркерами «•»; тексты —
`backend/app/subject_descriptions.py`,
сопоставление имён — нормализация + `ALIASES`). Типографика drawer —
`@atlaskit/heading` + `@atlaskit/primitives/compiled` (`Stack`/`Text`),
детали занятия — `Label` (`@atlaskit/form`), дата — `DatePicker`
(`appearance="subtle"`, `dateFormat="DD.MM.YYYY"` — собственный синтаксис
токенов пикера, не date-fns; интерактивный диалог-триггер открывает календарь),
время — два `TimePicker` (`timeFormat="HH:mm"`, без него — 12-часовой
«7:00 PM») для начала и конца пары через разделитель «–»; все пикеры
`isDisabled` — просмотр без возможности выбрать дату/время,
преподаватель — `Avatar` (инициалы
из имени), вид —
`Lozenge` (`KIND_APPEARANCE`, как в карточках), статус — `Lozenge` по общему
`STATUS_LABEL`/`STATUS_APPEARANCE` («Завершено», «Отменено», «Перенесено»,
«Идёт сейчас» — одинаково в карточках и drawer); действия — секция
«Действия»: `LinkButton appearance="primary"` с иконкой `video`
(нет ссылки — disabled-`Button` + подсказка), `Button` с иконкой
`calendar` («Добавить в календарь» пары; скролл-контент drawer идёт после
кнопки закрытия (offset 32 справа), поэтому снаружи задан
`paddingInlineEnd="space.400"` — одинаковые отступы слева и справа;
`DropdownItemLink` в dropdown-menu v18 нет — только onClick).
Lozenge для действий не используется. Оценки получают описание
вместе с `GET /grades`, расписание — через `GET /subjects?name=`
(матчинг: точное → нормализованное → префикс «Название (Организация)»
→ подстрока). Предмета нет в макете — заглушка «Информация о предмете
недоступна».
Важно: `React.StrictMode` отключён в `main.tsx` — `@atlaskit/portal` v6
теряет контент popup/drawer при двойном монтировании эффектов в dev.

## Тестирование

- `backend/tests/test_sync.py` — чистые функции парсера + мини-листы,
  собранные кодом в реальном формате (без бинарных фикстур).
- `backend/tests/test_api.py` — API на sqlite через подмену `get_session`;
  требуется `SKIP_DB_INIT=1` (иначе lifespan полезет в Postgres).
- `frontend/e2e/cabinet.spec.ts` — Playwright: вход → расписание → оценки,
  desktop + mobile 390px (проверка отсутствия горизонтального скролла).
  Требует запущенные backend (`SEED_DEMO=1`) и frontend dev.
