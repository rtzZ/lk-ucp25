# API

База: `http://localhost:8001`. Все ответы — JSON. Ошибки: `{"detail": ...}`.
Интерактивная документация: `/docs`.

## Авторизация

Все эндпоинты, кроме `/health` и `/auth/config|request_password|login`,
требуют заголовок `Authorization: Bearer <token>`; без него или с истёкшим
токеном — `401`. Токен выдаёт `POST /auth/login` по временному паролю,
который присылает Telegram-бот. Сессия живёт `SESSION_TTL_DAYS` (30 дней).

Первый вход: студент пишет боту `/start`, бот проверяет членство в группе
курса (`TELEGRAM_GROUP_ID`) и привязывает Telegram к ФИО из ведомости
(«кто первый»; снять привязку — `python -m app.admin unbind "Фамилия Имя"`).

Перебор ограничен rate limiter'ом с IP (запрос пароля 5/мин, вход 10/мин) —
сверх лимита `429`; плюс 5 неверных вводов на один пароль.

`Student`: `id, group, code, last_name, first_name, full_name`.

## `GET /auth/config` — настройки экрана входа

`{"telegram": true, "bot_username": "lk_bot", "dev_mode": false, "group": "УЦП-25"}`.
`bot_username` пуст, пока бот не стартовал.

## `POST /auth/request_password` — пароль в Telegram

Тело: `{"last_name": "Иванов", "first_name": "Иван"}` (регистр и `ё` не важны).

- `200` → `{"sent": true, "dev_password": null}` — **одинаково** для
  несуществующего ФИО, непривязанного Telegram и не-участника группы
  (ответ не раскрывает состав группы). Пароль — 6 цифр, живёт 60 секунд
  (в сообщении — `<code>`, копируется по нажатию);
  повторная отправка не чаще раза в 30 с.
- `502` — Telegram недоступен; `503` — бот не настроен.
- `AUTH_DEV_MODE=1` (только без `TELEGRAM_BOT_TOKEN`): пароль приходит
  в `dev_password`, Telegram не используется, лимиты выключены — для
  разработки и E2E.

## `POST /auth/login` — вход по паролю

Тело: `{"last_name": "Иванов", "first_name": "Иван", "password": "123456"}`.

- `200` → `{"token": "...", "student": {...}}`. Пароль одноразовый.
- `400` — `«Неверный или истёкший пароль. Запросите новый.»`; после
  5 неверных вводов пароль сгорает.

## `GET /auth/me` — текущий студент

Клиент проверяет им сохранённый токен при старте. `401` — войти заново.

## `POST /auth/logout` — выход

Отзывает текущий токен. `204`.

## `GET /schedule` — расписание

Расписание группы текущего студента. Параметры: `date_from`/`date_to` (ISO
`YYYY-MM-DD`), `kind` (`lesson | attestation | event | deadline`).
Сортировка: дата, время, id.

Запись: `id, group, date, time_start, time_end, subject_text, teacher, org,
lesson_no (nullable), kind, status (active|cancelled|moved|live|completed),
note, link (только http(s), "" если нет)`.

`live`/`completed` для активных записей считаются на лету при чтении
(БД не меняется); персистентный перевод в `completed` делает фоновый джоб
раз в `EXPIRE_INTERVAL_HOURS` (по умолчанию час).

Пример: `/schedule?date_from=2026-02-09&date_to=2026-02-15`.

## `GET /grades` — свои оценки

Только оценки владельца токена. Параметр: `semester` (опционален, точное имя
листа, например `1 семестр 25-26`). Сортировка: семестр, предмет.

Оценка: `id, subject, semester, attestation (экзамен|зачет|зачет с оценкой|""),
value (как в ведомости: "5", "зачтено", баллы; "" — оценки ещё нет),
verbal, ects, score (nullable),
description` (см. `GET /subjects`) — сырые значения ведомости, плюс разбор
по официальной шкале (`app/grading.py`):

- `five` — пятибалльный эквивалент (`«Отлично»`/`«5»` → 5; зачёт → `null`);
  по нему считается средний балл;
- `passed` — бинарная система (≥ 3 / «зачтено» → `true`);
- `label` — «Отлично» / «Хорошо» / … / «Зачтено» / «Не зачтено»;
- `ects_letter` + `ects_source` (`sheet` — из ведомости, `score` — по баллам,
  если в ведомости буквы нет);
- `status` — `final` (оценка в ведомости) | `provisional` (семестр закрыт,
  оценки нет, но есть баллы — оценка по шкале) | `in_progress` (семестр
  идёт, баллы копятся) | `none`; семестр закрыт, если оценка проставлена
  у ≥ 50% его записей по группе;
- `mismatch` — текст, если ведомость противоречит шкале («В ведомости ECTS
  «A», а 55 баллов по шкале — E»); значение ведомости не исправляется.

## `GET /grades/scale` — официальная шкала

`[{"lo": 95, "hi": 100, "traditional": "Отлично", "five": 5, "passed": true,
"ects": "A"}, …, {"lo": 0, "hi": 54, …, "passed": false, "ects": "F"}]`.

## `GET /subjects` — описание предмета

`?name=` — свободное название (для расписания подходит `subject_text`
с суффиксом организации). Матчинг: точное → нормализованное (регистр,
`ё`, `«(по выбору)»`) → префикс → подстрока. `404` — нет в базе.

`Subject`: `id, name, description` — описание из Figma-макета
(`about` — «Описание дисциплины», `skills_title`/`skills` — «Чему вы
научитесь», `content_title`/`content` — «Содержание …»; всё пусто —
предмета нет в макете, фронт показывает заглушку).

## `GET /health`

`{"status": "ok"}`.

## Логирование

Каждый запрос пишется в stderr одной JSON-строкой (`loguru serialize=True`):

```json
{"text": "... | INFO | app.main:log_requests:54 - http_request\n",
 "record": {"extra": {"method": "GET", "path": "/health", "status": 200,
  "elapsed_ms": 35.6}, ...}}
```

Ошибки парсинга (`sync.py`) и запуски/падения фоновых задач — тем же логгером
с контекстом (`[оценки]`, `[расписание]`).
